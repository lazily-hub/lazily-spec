## Compatibility policy

Core remains pre-1.0, but a released Core symbol is kept compatible throughout its declared deprecation window; accidental breaks are defects.

A deprecated Core API remains compatible for at least 2 compatible cohorts and 90 days. Its profile entry names the replacement and earliest removal generation.

Exports outside the declared Core allow-list remain Preview. Their presence in an umbrella package does not grant Core compatibility or Beta status.

Each installed consumer runs at the binding's declared minimum and current toolchains, builds the distributable artifact, copies it outside the checkout, creates a clean temporary project, installs only that copied artifact, and exercises all four required scenarios through a declared Core entry point:

- `source-computed-effect`: A Source invalidates a Computed and an Effect observes the settled derived value.
- `batch-coalescing`: Multiple writes in one batch produce one settled effect rerun.
- `scoped-disposal`: Disposing a scope detaches its effects and prevents later reruns.
- `typed-context`: The binding's declared typed-context surface preserves context identity and rejects cross-context use where the language can express it.

A source-tree path dependency, an undeclared development dependency, a skipped scenario, or an example that only runs inside the package checkout is not qualifying evidence.
